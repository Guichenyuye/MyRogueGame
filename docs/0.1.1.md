## 1. 版本号规则

`0.n.m` 三段，各管一件事：

| 段 | 含义 | 什么时候动 |
|---|---|---|
| `0` | **测试阶段**。存档格式、类结构、数值都可能推倒重来，不承诺兼容 | 短时间不会动 |
| `n` | **重大版本**。新增一整个玩法系统（一个"切片"） | 0.2.0 = 成长系统，0.3.0 = 经济与事件 |
| `m` | **小更新**。在已有系统内改数值、修 bug、补界面细节 | 每次调平衡 / 修排版都 +1 |

约定：

1. `n` 增加时 `m` 归 0。
2. **一个版本号对应一份可运行的快照**，也就是对应 `docs/<版本号>.md` 这一份文档。
3. 文档只写"现在是什么"，不写"打算做什么"——后者统一放在最后一节。
4. 判断该动 `n` 还是 `m`：**玩家能做的事变多了 → n；同样的事做得更顺 → m**。

已发出的版本：

| 版本 | 内容 | 文档 |
|---|---|---|
| 0.1.0 | 切片一：一场战斗（数值 + 控制台验证 + 战斗界面） | 未单独成文 |
| 0.1.1 | 切片二：一章节点地图；战斗界面排版返工；日志/字符清理 | 本文件 |
| 0.1.2 | 成长系统前置：天赋/技巧展示、CD 重置、金币经验字段、日志前缀上色 | `docs/0.1.2.md` |

> 0.1.0 当时只有一场战斗，没有独立文档，直接迭代到了地图。从 0.1.1 起每次发版留档。

## 2. 这个版本能玩到什么

```
主菜单 → 第 1 层（固定战斗）→ 地图 → 第 2~7 层（2~3 个分支选一）
                                        ├─ 战斗 → 战斗界面
                                        ├─ 精英 → 战斗界面（史莱姆王）
                                        ├─ 篝火 → 弹窗恢复 30% 生命
                                        └─ 宝箱 → 弹窗最大生命 +5
                                    → 第 8 层（首领）→ CLEARED
```

| 界面 | 已完成 | 操作 |
|---|---|---|
| 主菜单 `StartScreen` | 打字机标题、中文副标题、两个选项 | `1` 开始、`2`/`ESC` 退出 |
| 战斗 `GameScreen` | 左：HP/MP 条 + 护盾金边；右：敌人血条 + 下回合意图；中：自动换行滚动日志；底：四个技能框（冷却/蓝不足会变灰） | `1`~`4` 放技能 |
| 战斗结算 | 胜利 `VICTORY`（金边）/ 通关 `CLEARED`（金边）/ 失败 `DEFEAT`（红边），整屏不透明 | 胜利后 `Space` 回地图；失败 `ESC` 回主菜单 |
| 地图 `MapScreen` | 8 层竖排、已通过（灰）/ 当前（亮边 + 序号）/ 未探索（暗轮廓），三态一眼分得清 | 数字键选节点，非战斗节点 `Space` 推进 |

地图**可以看到未探索层的类型**，没做成 `???`。理由：这游戏信息密度本来就低，藏起来只会让人瞎选。

## 3. 代码清单

纯逻辑（不 import 任何 libGDX，可脱离窗口跑）：

| 类 | 职责 |
|---|---|
| `Player` | 归尘的面板、四技能槽、双 CD 数组、护盾生命周期 |
| `Skill` | 技能静态定义（枚举 `Id` 供分发，将来可换 JSON） |
| `Enemy` | 敌人抽象基类：`getIntent()` + `doTurn()` |
| `Slime` | 普通怪，撞击→强力撞击→包裹 循环，`bonus` 参数支持分层强化 |
| `SlimeKing` | 精英/首领共用，撞击→腐液→蓄力→重压 四步循环 |
| `BattleSystem` | **规则唯一权威**：回合流程、伤害、暴击、护盾、血之泪、胜负判定 |
| `MapNode` | 节点数据（类型 / 层 / 序号 / 是否已通过） |
| `GameMap` | 8 层生成：权重抽签 + 约束重抽 + 兜底 |
| `RunState` | 一局游戏的状态：唯一的 `Player`、层数、待进入节点、通关/失败标记 |
| `BattleTest` | 控制台自检，69 项断言 + 整章模拟 + 首领压力测试 |

界面层：

| 类 | 职责 |
|---|---|
| `Main` | `extends Game`，只持有共享资源（SpriteBatch / BitmapFont / FreeTypeFontGenerator） |
| `StartScreen` / `GameScreen` / `MapScreen` | 三个 Screen，各自只管画和读键盘 |
| `Ui` | 从 `GameScreen` 抽出的画图工具：`rect` / `frame` / `bar` / `text` / `measure` |

**分层原则**：Screen 不做任何数值计算，只读 `RunState` / `BattleSystem` 的字段、把按键翻译成方法调用。所以 `BattleTest` 不需要启动窗口就能验完整章。

## 4. 数值快照（代码里的实际值）

### 4.1 归尘

| 项 | 值 |
|---|---|
| 生命 / 精力 | 80 / 10（每回合开始回 1 点精力，上限 10） |
| 力量 / 精准 / 防御 | 5 / 5 / 5 |
| 暴击 | 5%，150% 伤害（全员固定，不可提升） |

### 4.2 四技能

| 槽 | 技能 | 精力 | CD | 原始伤害 | 打 1 防史莱姆实结算 |
|---|---|---|---|---|---|
| 1 | 普攻 | 0 | 0 | 力量×1.2+5 = **11** | 10 |
| 2 | 防御 | 1 | 0 | 护盾 = 防御×2 = **10** | — |
| 3 | 精准射击 | 3 | 2 | 精准×1.5+10 = **17**（17.5 截断） | 16 |
| 4 | 横扫 | 2 | 1 | 力量×1.0+6 = **11**（每个敌人） | 10 |

槽 1、槽 2 锁死不可替换；槽 3、槽 4 预留给精英节点的技能替换。

### 4.3 敌人

| 出处 | 敌人 | 生命 | 防御 | 行为 |
|---|---|---|---|---|
| 第 1~3 层战斗 | 史莱姆 | 30 | 1 | 撞 5 / 强撞 8 / 包裹（扣 1 精力，自身伤害永久 +2） |
| 第 4~6 层战斗 | 史莱姆（强化） | 34 | 1 | 同上，全部 +1 伤害 |
| 第 7 层战斗 | 史莱姆 + 小史莱姆 | 30 / 18 | 1 / 0 | 同上 / 同上（无加成） |
| 精英 | 史莱姆王 | 62 | 3 | 撞 7 / 腐液 9（扣 1 精力）/ 蓄力 / 重压 16 |
| 首领 | 腐化史莱姆王 | 95 | 4 | 撞 8 / 腐液 10 / 蓄力 / 重压 18 |

**蓄力**是这套战斗里唯一的强制决策点：意图栏提前一整回合显示"下回合重压 18 伤害"，玩家有一个完整回合决定防御还是抢伤害。这个不能省，省了史莱姆王就只是血厚一点的史莱姆。

### 4.4 地图生成

| 参数 | 值 |
|---|---|
| 总层数 | 8（第 1 层固定战斗，第 8 层固定首领） |
| 第 2~7 层分支数 | 3 个的概率 0.55，否则 2 个 |
| 权重 | 战斗 38 / 篝火 22 / 宝箱 20 / 精英 20 |
| 楼层门槛 | 篝火 ≥ 3 层、宝箱 ≥ 2 层、精英 ≥ 4 层 |
| 同层约束 | 篝火 / 宝箱 / 精英各最多 1 个，且至少有 1 个战斗类节点 |
| 兜底 | 重抽 20 次仍不合法 → 强制普通战斗 |

实测 1000 局：战斗 51.2%、精英 11.1%、篝火 14.5%、宝箱 17.2%、首领 6.0%，非战斗合计 **31.7%**（断言区间 25%~40%）。

> 权重看起来"篝火比战斗少不了多少"，但实际战斗占了一半——因为同层去重后要重抽，重抽池里战斗权重最大，等于变相加权。**调权重必须看实测分布，不能看表面数字。**

### 4.5 非战斗节点

| 节点 | 效果 |
|---|---|
| 篝火 | 恢复 `maxHp × 30%`（至少 1 点） |
| 宝箱 | 最大生命 +5，同时当前生命 +5 |
| 事件 / 商店 | **本版不生成**，枚举占位 |

## 5. 已敲定的规则（改之前先看这里）

1. **防御双向生效**：玩家打怪、怪打玩家都套 `伤害 × (1 - 防御/(防御+25))`，`K = 25`。
2. **最低 1 点**：减伤后不足 1 按 1 算，防御再高也不会完全免疫。
3. **统一向下取整，中间用 double**：所有公式先按 double 算，最后一次性 `(int)` 截断，不做四舍五入。
4. **先减伤再扣盾**：护盾吃的是减伤后的伤害，不是原始伤害。
5. **护盾刷新不叠加**：重复上盾只覆盖数值，持续时间仍为 1 个敌方回合，敌方行动结束即清空（没被打完也清空）。
6. **血之泪按"伤害次数"触发**：每次对敌人造成伤害回 1 点血；横扫打 2 个目标就回 2 点。这是刻意的，AOE 就该有回报。
7. **CD1 = 隔一回合**：第 N 回合用，N+1 不可用，N+2 可用。实现上是双数组（真实 CD + 显示 CD），回合开始先抄再减。
8. **每层至少一个战斗节点**：不允许整层白嫖，否则玩家必然全选安全路线，节奏就塌了。

## 7. 已知问题与技术债

| 问题 | 影响 | 计划 |
|---|---|---|
| **打赢没有任何成长** | 8 场打下来角色数值一点没变，只有血之泪回几点血。一局内没有构建感 | 0.2.0 解决 |
| 无金币、无商店、无事件 | 地图上只有"打 / 回血 / 加血上限"三种事，选择很浅 | 0.3.0 |
| 节点之间**没有连边** | 当前层任意节点都能通向上一层任意节点。要做"路线互斥"得给节点加边表，容易把一局堵死 | v0.2 后再评估 |
| 数值全部硬编码在 Java 里 | 调平衡要改代码重编译 | 数值稳定后抽到 JSON |
| 没有存档 | 退出即丢，一局必须一口气打完 | 有成长系统之后才有必要 |
| 多段攻击会让血之泪超模 | 现在没有多段技能，加之前要先裁定"每段是否各回 1 血" | 待定 |
| 第 7 层双史莱姆未经真机验证 | 界面已支持多敌人面板，但只测过单敌人 | 下次回归补 |
| 无音效、无 BGM、无动画 | 纯文字表现，打击感全靠日志 | 靠后 |
| 原始设计文档未入库 | 只在对话里，`docs/` 下没有正式版 | **0.1.2 补** |
