# 归尘 · 0.2.1 — 体验修正（天赋红白闪烁 + 三选一必出 + 属性点可反悔）

> **一句话**：不打乱 0.2.0 的成长系统，只修三处玩家体验痛点——天赋触发不再放大而是红白闪、三选一改成每战必出、属性点分配可以反悔且没分完不能继续。

- 整理时间：2026-11-03
- 对应代码：`core/src/main/java/com/myname/roguelike/`（新增 `AttributeAllocator`，改 `GameScreen` / `ResultScreen` / `Player` / `RunState`）
- 复核方式：`./gradlew :core:battleTest` → 126 项全过

---

## 1. 这个版本改了什么

0.2.0 的成长闭环能跑通，但有三处体验硬伤，这一版逐个修掉：

1. **天赋触发动画**：原来是「放大 1.5 倍」，会挤压布局、显得廉价。改成**字号位置绝对不变**，只做红白交替闪烁（0.5 秒内 0.1 秒切一次），结束后恢复金色。
2. **三选一触发时机**：原来绑在「升级」上，导致玩家可能很久拿不到技巧。改成**每次战斗胜利必弹一次三选一**，选完才结算经验升级，升级不再重复触发三选一。
3. **属性点分配**：原来是「一次性确认、不可反悔、没分完也能继续」。改成**临时池 + 可反悔（加减）+ 置灰确认**：没分完点数时「继续」按钮置灰且空格无效。

---

## 2. 玩家能玩到的流程（新版）

```
战斗胜利 → 结算界面（金币 +X / 经验 +X / 进度条 / 等级）
        → 按空格 → 必弹三选一（技能升级 / 属性点 / 战斗技巧）   ← 每战必出，不再看经验
        → 选完 → 结算经验升级（只发 +2 属性点，不再弹三选一）
        → 有待分配属性点？是 → 属性分配（临时池：加/减/反悔，分完才能继续）
        → 结算完成 → 按空格回地图
```

| 界面 | 内容 | 操作 |
|---|---|---|
| 结算页 | 金币、经验、进度条、等级 | 空格继续 |
| 三选一 | 三个奖励（技能升级金 / 属性点绿 / 技巧蓝） | `1` `2` `3` 选择 |
| 属性分配 | 四项属性 + `[-]` `[+]` 按钮 + 剩余点数 | `1`~`4` 加、`Q`/`W`/`E`/`R` 减，或鼠标点按钮；空格确认 |

## 3. 代码清单（本版改动）

| 类 | 改动 |
|---|---|
| `AttributeAllocator`（新增） | 纯 Java 临时池状态机：`add/sub/remaining/pendingAt/canContinue/commit`，供 UI 和 BattleTest 共用 |
| `Player` | 加 `talentFlashR/G/B` 三个 float 字段（默认红），不 import libGDX 保持纯 Java |
| `GameScreen` | 天赋绘制去掉 1.5 缩放，改纯颜色闪烁（`FLASH_SECONDS=0.5`、`FLASH_STEP=0.1`）；行高 `ROW_H` 34→30 |
| `ResultScreen` | 流程改为「必弹三选一 → 结算升级 → 属性分配」；属性分配改用 `AttributeAllocator`，加键盘加减 + 鼠标 `[-]` `[+]` 按钮 + 置灰确认 |
| `RunState` | 加 `settleLevelUps()`（一次性结算所有升级，只发属性点） |
| `BattleTest` | 104 → 126 项断言 |

**分层原则不变**：`ResultScreen` 只做展示和转发按键/鼠标，可反悔逻辑全在 `AttributeAllocator`（纯 Java），所以控制台能直接测。

## 4. 三条改动细则

### 4.1 天赋红白闪烁

- `Player` 用三个 float 存闪光色（`talentFlashR/G/B`，默认红 1.0/0.2/0.2），而不是 libGDX 的 `Color`——因为 Player 是纯 Java，BattleTest 直接跑。
- `GameScreen` 闪烁期间：按 `剩余时间 / 0.1s` 的奇偶段切换「闪光色 ↔ 纯白」，0.5 秒后回默认金色 `TALENT_TEXT`。
- **字号和位置全程 1.0 倍不变**，彻底消除布局抖动。
- 扩展性：以后不同角色设不同的 `talentFlashR/G/B` 即可，强化角色辨识度。

### 4.2 三选一每战必出

- `ResultScreen.advanceFromResult()`：RESULT 按空格后**无条件** `rollChoices()` 进 CHOICE，不再判断经验。
- `ResultScreen.finishChoice()`：选完后调 `run.settleLevelUps()` 一次性结清所有升级（只发 +2 属性点），再进属性分配/完成。
- 保底机制不变：`skillUpgradeMissCount` 连续 2 次没出技能升级，第 3 次强制全出。
- 首领通关（`cleared`）仍直接回主菜单，不经过三选一——通关后已无构筑意义。

### 4.3 属性点可反悔 + 置灰

- 临时池：加减操作只改 `AttributeAllocator.pending[]`，**绝不**实时写 `Player`。
- 加：`1/2/3/4` 或点 `[+]`；减：`Q/W/E/R` 或点 `[-]`（下限 0）。
- 置灰：`remaining() > 0` 时「继续」按钮画暗灰色，空格/回车无效。
- 确认：只有 `canContinue()`（剩余归 0）时 `commit()` 才把临时值一次性写进 `Player`，并把全局待分配点归零。

## 5. 已敲定的规则（本版变更）

1. **天赋触发不缩放**：字号位置永远 1.0 倍，反馈只靠颜色。
2. **三选一与升级解耦**：战斗胜利必出三选一，经验升级只发属性点、不触发三选一。
3. **属性分配临时池制**：确认前 Player 面板一字不动，`canContinue()` 为 false 时确认无效。
4. **键鼠并存交互**：这版在属性分配界面固化「键鼠并存」的交互模式，后续三选一/商店/事件面板照此模板做。

./gradlew :core:battleTest   # 126 项全过

新增断言覆盖：战斗胜利必弹三选一（经验不足 / 富余两种情况都是 3 个选项）、属性分配临时池全链路（+1 → 剩余 1 且 canContinue=false → 退点恢复 2 → 加满 0 点 canContinue=true → commit 后真实面板 +1/+1）、反悔边界（没加点不退成负、剩余 >0 时 commit 拒绝）。
