# 节点地图设计 v0.1（切片二）

> 目标：打完第一只史莱姆之后，不再弹回主菜单，而是走进一张能"往上爬"的地图。
> 本文件只定**结构和规则**，界面细节在同一版代码里实现。

---

## 1. 章节结构

一章 = **8 层**。

| 层 | 节点数 | 规则 |
|---|---|---|
| 1 | 1 | 固定普通战斗，教学节点，没有选择 |
| 2 ~ 7 | 2 或 3 | 分支层，玩家选 1 个进入 |
| 8 | 1 | 首领 |

- 一局完整跑完第一章约 **8 个节点**（含首领），按目前战斗 3~6 回合的节奏，15~25 分钟。
- 暂时只有一章。多章（第二、三章敌人换皮 + 数值上调）留到内容量够的时候再开。

示意图（每层内部横向是并列选项，纵向是推进方向）：

```
  层 8        [ 首领 ]
                 |
  层 7    [ 精英 ]      [ 篝火 ]
              \          /
  层 6      [ 宝箱 ]  [ 战斗 ]
                 \    /
  层 5        [ 战斗 ]  [ 篝火 ]
                  \     /
  层 4          [ 精英 ]
                    |
  层 3      [ 战斗 ]  [ 宝箱 ]
                 \    /
  层 2        [ 战斗 ]  [ 篝火 ]
                    |
  层 1           [ 战斗 ]        ← 固定，教学
```

> 连线只表示"可以往上走"，不表示严格的一对一通路。
> 也就是说：**当前层的任意节点都能通往上一层的任意节点**。
> 真要做出「路线互斥」（走了左路就上不去右边），需要给节点加边表，
> 那是 v0.2 的事，本版先用全连通，避免一局被堵死。

---

## 2. 节点类型

| 类型 | 界面标记 | 内容 | 是否进战斗 | 本版 |
|---|---|---|---|---|
| BATTLE | 战斗 | 史莱姆，数量随层数增加 | 是 | ✅ |
| ELITE | 精英 | 史莱姆王 | 是 | ✅ |
| BOSS | 首领 | 腐化史莱姆王 | 是 | ✅ |
| REST | 篝火 | 恢复 30% 最大生命 | 否 | ✅ |
| TREASURE | 宝箱 | 最大生命 +5 并回满那 5 点 | 否 | ✅ |
| EVENT | 事件 | 文字三选一 | 否 | ⬜ v0.2 |
| SHOP | 商店 | 花金币买卡/遗物/药水 | 否 | ⬜ v0.2 |

EVENT 和 SHOP 这一版**不参与生成**（枚举先留着），原因：
- 事件系统要先有"选项 → 效果"的数据结构，而且至少写 5~6 个事件才有意思；
- 商店要有金币产出与消费闭环，现在金币都没有稳定来源，开了也是空架子。

---

## 3. 生成规则

```java
// 第 1 层
[ BATTLE ]

// 第 2 ~ 7 层
count = rng < 0.55 ? 2 : 3
每个节点按权重抽类型：
    BATTLE    38
    REST      22   （floor >= 3 且本层还没有篝火）
    TREASURE  20   （floor >= 2 且本层还没有宝箱）
    ELITE     20   （floor >= 4 且本层还没有精英）
    EVENT      0   （v0.2 再开）

约束（抽到不合法的就重抽，最多 20 次，兜底 BATTLE）：
    1. 同一层最多 1 个篝火 / 1 个宝箱 / 1 个精英
    2. 精英不出现在第 1~3 层
    3. 篝火不出现在第 1~2 层
    4. 每层至少有 1 个战斗类节点（BATTLE 或 ELITE）
       —— 否则会出现"整层都是白嫖"，一局下来一场不打

// 第 8 层
[ BOSS ]
```

第 4 条是刻意加的：肉鸽的乐趣来自「资源换风险」，如果一层能全避开战斗，
玩家会本能地全选安全节点，节奏就塌了。

**权重不能按"想要的占比"直接写。** 因为同层不允许重复，抽到重复要重抽，
而重抽的池子里 BATTLE 最大，等于给 BATTLE 变相加权。第一版按 62/14/12/12 写，
实测 1000 局出来是 **战斗 72%**，一局 8 个节点能打 7 场，节奏闷得没法看。
压到 38/22/20/20 之后实测：

| 类型 | 占比 | 说明 |
|---|---|---|
| 战斗 | 51.2% | 玩家实际走的 8 层里约 4~5 场 |
| 精英 | 11.1% | |
| 篝火 | 14.5% | |
| 宝箱 | 17.2% | |
| 首领 | 6.0% | 固定 1 个 |

非战斗节点合计 **31.7%**，落在 25%~40% 的合理区间。`battleTest` 里有这条断言，
以后调权重直接看输出，别凭感觉。

## 4. 敌人配置

| 节点 | 层数 | 敌人 | 血量 | 防御 |
|---|---|---|---|---|
| 战斗 | 1 ~ 3 | 史莱姆 ×1 | 30 | 1 |
| 战斗 | 4 ~ 6 | 史莱姆 ×1（强化，伤害 +1） | 34 | 1 |
| 战斗 | 7 | 史莱姆 ×2（小只的 18 血 0 防） | 30 / 18 | 1 / 0 |
| 精英 | 任意 | 史莱姆王 | 62 | 3 |
| 首领 | 8 | 腐化史莱姆王 | 95 | 4 |

**史莱姆王**（精英 / 首领共用同一套行为，只是数值不同）四步循环：

| 步 | 行动 | 精英 | 首领 |
|---|---|---|---|
| 0 | 撞击 | 7 | 8 |
| 1 | 腐液（扣 1 精力） | 9 | 10 |
| 2 | 蓄力（本回合不出手，意图可见） | — | — |
| 3 | 重压 | 16 | 18 |

「蓄力」这一拍是给玩家看的：意图栏会提前显示 `蓄力 (下回合重压 18 伤害)`，
玩家有整整一个回合决定要不要防御。这是这套战斗系统里**唯一一个强制性决策点**，
不能省。

**首领数值是这么定下来的**：玩家 80 血、每回合打 9 点左右，95 血 = 11 回合左右；
期间承伤约 7.5/回合。`battleTest` 里有一段「笨 AI」对战（血低于 30 就防御、
有蓝就精准射击、否则普攻），实测 **11 回合、剩 18/80 血通关**。
这是个很窄的胜利窗口，正是想要的——再多 10 点血玩家就必死，再少 10 点就没压力。
第一版按 110 血 / 20 重压试过，纯普攻必输，属于劝退关卡。

## 5. 界面布局

```
+--------------------------------------------------------------+
|  归尘   HP 62/80   MP 7/10      腐叶浅林   第 3 / 8 层        |  ← 顶栏
+--------------------------------------------------------------+
|                                                              |
|                       [ 首领 ]                               |
|                           |                                  |
|                  [ 精英 ]     [ 篝火 ]                        |
|                       \       /                              |
|                    [ 宝箱 ] [ 战斗 ]                          |
|                        \     /                               |
|                      [ 战斗 ] [ 篝火 ]                        |
|                           |                                  |
|                        [ 战斗 ]  ← 当前层，黄色高亮            |
|                                                              |
+--------------------------------------------------------------+
|  按 [1] [2] 选择节点    [ESC] 放弃本局                        |  ← 底栏
+--------------------------------------------------------------+
```

三种状态：

| 状态 | 表现 |
|---|---|
| 已通过（floor < 当前层） | 整块压暗到约 40% 亮度，不可选 |
| 当前层 | 亮底 + 彩色描边 + 一圈外发光，左上角标 `[1]` `[2]` |
| 未探索（floor > 当前层） | 暗色轮廓，类型文字可见但压暗，不能选 |

> 未探索层故意**显示类型**而不隐藏成 `???`：
> 这套游戏的信息密度本来就低，藏起来只会让玩家瞎选，不会增加乐趣。

节点框里**只有一行类型名**。第一版试过"类型 + 副标题"两行（`战斗 / 史莱姆`），
结果：框高不够，第二行只能缩到 0.85 倍，像素字体在非整数缩放下会渗色，
第二行文字被下边框拦腰穿过；而且「战斗 / 史莱姆」这种副标题本来也不提供信息。
一条都留不下，直接砍成单行。

非战斗节点（篝火 / 宝箱）在地图上选中后不切屏，直接在中间弹一个结算框，
按空格推进到下一层。

## 6. 状态流转

```
主菜单 --[1]--> 第 1 层战斗 --> 胜利 --> 地图(第 2 层)
                                    |
                                    +-- 选战斗/精英 --> 战斗 --> 胜利 --> 地图(下一层)
                                    |
                                    +-- 选篝火/宝箱 --> 结算框 --> [空格] --> 地图(下一层)

任意战斗失败 --> 主菜单（本局结束）
首领战胜利   --> 通关结算
```

**关键点**：`Player` 对象在整局里只有一个，血量、精力、最大生命在节点之间**连续**，
所以篝火才有意义、宝箱的 +5 最大生命才需要精打细算。

## 7. 本版刻意没做的事

| 项 | 原因 |
|---|---|
| 事件 / 商店 | 见第 2 节 |
| 金币 | 没有消费口，先不产 |
| 路线互斥 | 见第 1 节 |
| 三选一成长（升级后选卡） | 下一刀。现在打赢只给血之泪那点回血，没有成长感 |
| 存档 | 一局 20 分钟，先不做 |
| 多章节 | 内容量不够 |

## 8. 接下来该定的

1. **升级与三选一**：斐波那契经验表已在文档里，但打赢节点给不给经验、升级时给什么，还没定。
2. **精英节点的技能替换**：文档 3.6 提到"精英节点技能二选一替换槽 3/槽 4"，要等有第二个技能池才成立。
3. **蓄力类机制的通用化**：现在史莱姆王的蓄力是写死的 `step == 2`，
   将来如果多个敌人都有蓄力，应该抽成 `Intent` 数据而不是每个怪各写一遍。

## 9. 实施记录（v0.1 已完成）

| 文件 | 职责 |
|---|---|
| `MapNode` | 节点数据 + 类型枚举（label / 是否战斗） |
| `GameMap` | 8 层生成、权重抽签、约束重抽、ASCII 预览 |
| `RunState` | 一局的状态：唯一的 `Player`、地图、当前层、待进入节点、通关/失败标记 |
| `MapScreen` | 地图渲染、数字键选节点、篝火/宝箱结算框 |
| `Ui` | 从 `GameScreen` 抽出来的画图工具（矩形、边框、进度条、文字、任意两点连线） |
| `SlimeKing` | 精英 / 首领共用，四步循环 |

已验证：

- `./gradlew :core:battleTest` **69 项断言全过**，含地图生成约束 ×5 个种子、1000 局分布统计、
  整章流程不死循环、首领战笨 AI 可通关。
- 真机完整跑通：主菜单 → 第 1 层战斗 → 地图 → 宝箱 → 第 3 层 → 第 4 层精英（蓄力/重压意图可见）
  → 首领 → CLEARED → 回菜单。截图在 `docs/screenshots/`。

调试入口（正式版可以留着，不影响随机局）：

```bash
ROGUE_SEED=2026 java -jar MyRogueGame.jar     # 固定地图
ROGUE_FLOOR=8   java -jar MyRogueGame.jar     # 直接从首领层开局
```
